# AI 主动阅读闭环

## Feature Status

- Status: Proposed
- Priority: P1
- Target release: Unscheduled
- Initial format scope: EPUB
- Product basis: 《如何阅读一本书》中的检视阅读、主动提问、分析阅读和自我测验方法

## Summary

将现有 AI 阅读工作台从以对话和单次文本分析为主的工具，扩展为贯穿读前、读中和读后的主动阅读教练。第一阶段落地四项能力：检视阅读向导、四个主动问题、章节自测和难点暂存箱。

工作台增加“阅读教练 / 对话”一级切换，历史会话、专家和来源入口保持不变。所有 AI 请求都由用户确认触发，默认采用“用户先回答、AI 再提示和校正”的顺序，不增加更多显性的 Agent 按钮。

## Product Behavior

### 检视阅读向导

- EPUB 目录加载完成且本书没有检视记录时，显示“开始检视 / 稍后 / 不再提醒”的本地提示，不自动调用模型。
- 开始前要求用户填写“我认为本书在谈什么”，阅读目标为可选项。
- 输入只包含书籍元数据、完整目录和最多 6 个代表章节，不上传整本书。
- 章节样本包含开头 2000 字和结尾 1000 字；样本覆盖前置内容、前两个正文节点、均匀分布的中间节点和最后正文节点，并按 href 去重。
- 输出包含书籍类型、核心问题、结构概览、关键章节、建议阅读层次、阅读计划、不确定项和可定位的章节引用。
- 报告按书缓存。手动重新生成时保留用户原有回答，并记录模型、供应商、提示版本和生成时间。

### 四个主动问题

每本书固定保存以下四个问题：

1. 整体来说，这本书到底在谈些什么？
2. 作者细部说了什么，怎么说的？
3. 这本书说得有道理吗，是全部还是部分有道理？
4. 这本书跟我有什么关系？

- 用户答案本地自动保存，并保留修订历史。
- 答案为空时不能请求 AI 提示或评估。
- AI 提供逐级提示、优点、遗漏、追问和原文证据，不覆盖用户答案，也不把模型输出伪装成标准答案。
- 原文证据必须关联章节 href；点击后返回对应章节。
- “说得有道理吗”允许复用现有内部专家和事实核查能力，但默认不联网。

### 章节自测

- 阅读器在内存中跟踪每章达到过的最高页码比例。
- 当上一章达到 80% 且切换到下一章时，显示非阻塞提醒；目录跳转、重复 relocation 和未知总页数不应误触发。
- 用户确认后才读取上一章并生成 3 道开放题，覆盖内容复述、关键主张或结构、联系或批评。
- 用户必须先提交自己的答案，之后才能查看提示和评估。
- 反馈采用“待复习 / 基本掌握 / 理解扎实”三级掌握度，不使用百分制。
- 重新生成会创建新的自测尝试，历史答案和反馈保持可查看。
- 选择“稍后”或生成失败的章节继续显示在阅读教练总览中，不反复阻断阅读。

### 难点暂存箱

- 长按选区菜单的“更多”和 AI 选区动作卡都增加“暂存难点”。
- 暂存操作只写本地数据，不调用 AI，也不混入普通划线笔记。
- 保存书籍、章节、CFI、选中文本、相邻上下文、用户备注和处理状态；相同书籍、CFI 和文本应去重。
- 未解决难点在正文中显示高对比虚线下划线，兼容横排、竖排和 E-INK。
- 点击标记打开阅读教练中的难点详情，可定位原文、请求解释、添加备注或标记解决。
- 标记解决后移除正文下划线，但保留历史记录和 AI 处理结果。
- 切章提醒合并显示待处理难点数量和章节自测入口，避免连续弹窗。

## Architecture And Data

数据库版本从 11 升级到 12，新增以下数据表：

- `tb_reading_guides`：按 `book_id` 保存检视状态、读前判断、阅读目标、报告、四个问题、答案修订记录和生成元数据。
- `tb_reading_quizzes`：按书籍和章节保存提醒状态、题目、用户答案、AI 反馈、掌握度和历史尝试。
- `tb_reading_difficulties`：保存难点位置、上下文、备注、状态、解决结果和时间字段。

新增主要接口：

- `InspectionReadingGuide`
- `ActiveReadingQuestion` / `AnswerRevision`
- `ChapterQuiz` / `QuizAttempt` / `ReadingMasteryLevel`
- `ReadingDifficulty` / `ReadingDifficultyStatus`
- `ReadingCoachRepository` 和按 `bookId` 隔离的 Riverpod provider
- `ChapterContentHandlers.fetchChapterSampleByHref(...)`

foliate-js 批注接口增加独立 `annotationKey`，将批注身份与 CFI 分离，使难点标记可以和相同 CFI 的普通划线共存。旧批注不提供 `annotationKey` 时继续使用原有 CFI 行为。

AI 结构化返回必须经过 schema 校验。无法解析时使用同一请求纠正一次；仍失败则保留原数据、记录可诊断日志并展示可重试错误。调用复用现有通用 AI 模型、备用供应商和内部多 Agent 调度。

所有数据进入现有 SQLite 数据库，因此自动使用现有 WebDAV 数据库同步。软删除书籍时保留阅读成果，永久删除时随书清理。

## UI And Accessibility

- 工作台仍默认打开现有对话页；首次检视提示或用户点击“阅读教练”后进入教练页。
- 阅读教练总览依次展示检视报告、四个问题进度、待完成章节自测和未解决难点。
- 宽屏继续使用可调宽右侧分栏，手机继续使用全屏工作台。
- 隐藏工作台、查看历史或切换对话时，不销毁草稿、滚动位置或阅读教练状态。
- E-INK 使用纯黑边框、虚线、字重和静态状态表达，不依赖透明色和动画。
- 新文案提供英文和简体中文，其他语言使用英文回退。

## Failure And Privacy Rules

- 未配置 AI 时，四个主动问题和难点箱仍可离线使用；需要生成的功能展示 AI 配置入口。
- 检视、自测和普通反馈默认只使用本书内容，不自动联网。
- 章节正文抽样必须有字符上限，不把整本书作为单次模型上下文。
- AI 失败不得覆盖用户答案、已有报告、自测记录或难点状态。
- 模型推断和原文内容必须在界面中明确区分，引用无法定位时不得伪造位置。

## Acceptance Tests

- 数据库从版本 11 升级后新表、索引和默认值正确，旧书籍、笔记及 AI 会话不受影响。
- 检视抽样覆盖前、中、后章节和章节头尾，并严格执行数量与字符上限。
- 首次提示、稍后、不再提醒、缓存复用和手动重新生成状态正确。
- 四个问题在空答案时不能调用 AI，答案修订和反馈可跨重启恢复。
- 章节达到 80% 后切章只提醒一次，目录跳转和未知页数不会误触发。
- 自测题缓存、历史尝试、三级掌握度、脏返回纠正和失败重试正确。
- 难点去重、原文定位、普通批注共存、点击打开和解决后移除正确。
- Widget 测试覆盖阅读教练/对话切换、移动端全屏、宽屏分栏和 E-INK。
- foliate-js 重新构建后通过 Chrome 83 兼容验证，并完成 Flutter 单元测试和 `flutter analyze`。
- macOS 与 Android 真机完成 EPUB 检视、切章提醒、自测和难点处理验收。

## Out Of Scope

- PDF、TXT 或其他非 EPUB 格式的章节闭环。
- 自动上传整本书、自动联网或后台自动调用模型。
- 用户自定义阅读方法和可视化 Agent 编排。
- 跨书主题阅读、作者术语表、命题图和长期间隔复习；这些作为后续阶段单独规划。
